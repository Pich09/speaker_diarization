One-shot process

  1. Data audit6,900 simulated meetings, 130.37 h, 20 speakers; clean read-speech, no noise or reverb.
  2. Environment setupDiariZen + pyannote-audio, Windows audio fallback, PyTorch embedding loading, Perl for dscore.
  3. Model and checkpointv2 model plus WeSpeaker ResNet34 embedding; 599/599 checkpoint keys matched.
  4. Speaker-disjoint holdoutTrain 1.027 h, dev 11.497 h, test 82 meetings / 1.699 h; designated test speakers excluded from train meetings.
  5. Zero-shot baselineDiarized all 82 test files with the v2 pipeline and wrote per-file RTTMs.
  6. Score with dscoreOverall DER 9.58% at 0.25 s collar; JER and B3 metrics also recorded.
  7. Frozen-WavLM pilotNot started. Gate target is DER ≤ 8.58%. A 4 GB GPU VRAM probe is the next step.

What “one-shot” means

One gated pilot experiment, not one-shot speaker enrollment or a production model. Passing the gate only justifies building a real Khmer evaluation set and a larger pilot.

Caveats

  • Simulated clean read-speech, not real Khmer conversation; domain transfer is likely poor.
  • Only 20 speakers; top-5 speakers dominate the training data.
  • Source-cut overlap between train and test remains (3 train/test overlaps).
  • Fine-tuning adapts segmentation only; embedding and PLDA stay domain-mismatched.
